# EventFlow Participant Manager

## Когда использовать

Используй этот Skill, когда нужно построить или проверить локальное приложение
организатора события: показатели, список участников, CRUD, поиск и фильтры,
импорт CSV с предпросмотром, резервные копии JSON и журнал действий.

## Границы

- Skill не расширяет разрешения агентов. Каждый агент действует только в рамках
  своих прав.
- `data/` и `references/` доступны только для чтения.
- Нельзя выдумывать людей, компании, статусы, билеты и даты.
- Приложение создаётся и изменяется только внутри `app/`.
- Данные хранятся только в IndexedDB; массив в памяти и `localStorage` не
  заменяют базу.
- Нельзя добавлять фреймворки, сборщики, CDN, внешние шрифты, API, аналитику и
  сетевые запросы.
- Опасные действия требуют подтверждения или возможности отмены.
- Skill сам не изменяет файлы. Это делает Build после разрешения человека.

## Workflow

1. **Чтение исходников.** Прочитай `AGENTS.md`, `references/project-brief.md`,
   `references/acceptance-checklist.md`, `data/event-settings.json` и оба CSV.
   Зафиксируй модель участника, правила статусов и критерии готовности.
2. **`/data-plan`.** Спроектируй пользовательский путь, схему IndexedDB,
   конвейер CSV, экспорт/восстановление и состояния экрана. Не меняй файлы.
3. **Подтверждение.** Покажи человеку спорные правила, объём этапа и риски
   потери данных. Дождись явного разрешения.
4. **`/data-build`.** Реализуй только согласованный этап внутри `app/`.
   Сохраняй работающие части и явно описывай миграции схемы.
5. **Проверка.** Запусти `node scripts/validate.mjs` и пройди ручной сценарий из
   `docs/QA-CHECKLIST.md`, включая узкий экран и клавиатуру.
6. **`/data-qa`.** Передай приложение на независимый аудит. QA возвращает
   таблицу доказательств и один статус, но ничего не исправляет.
7. **Согласованные исправления.** После разрешения человека исправь только
   подтверждённые пункты и повтори проверку.

## Критерии результата

- Работают показатели, CRUD, поиск, фильтры, сортировка и check-in.
- Email уникален без учёта регистра.
- `checkedIn: true` допустим только для статуса `confirmed`.
- Архивация обратима, архивные записи не влияют на показатели.
- CSV сначала показывает предпросмотр; ошибочные строки не попадают в базу.
- Экспорт создаёт JSON `schemaVersion: 1`.
- Восстановление проверяет файл и требует отдельного подтверждения замены.
- Журнал действий отражает изменения и импорты.
- Нет сетевых запросов, внешних зависимостей и реальных персональных данных.
- Интерфейс читаем на 1440, 768 и 390 px и доступен с клавиатуры.
- `data/` и `references/` не изменены, QA вернул независимый отчёт.

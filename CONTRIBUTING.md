# Как внести вклад

Спасибо за интерес к EventFlow. Это небольшое локальное приложение, поэтому
главные требования — сохранять данные честными, а базу — предсказуемой.

## 1. Ветки

- `main` — стабильная версия, ветка по умолчанию;
- `develop` — интеграционная ветка;
- `feature/<краткое-имя>` — новая функциональность;
- `fix/<краткое-имя>` — исправление;
- `docs/<краткое-имя>` — документация.

Ветки создаются от `develop`, завершённая работа вливается в `develop`, затем
`develop` — в `main` через merge-коммит.

## 2. Коммиты

Используются Conventional Commits:

```text
feat: add CSV duplicate detection to the import preview
fix: keep check-in disabled for cancelled participants
docs: describe the IndexedDB schema
test: validate both CSV datasets and the sample backup
chore: add editor configuration
```

Сообщение — в императиве, на английском; тело коммита объясняет причину
изменения, если она не очевидна.

## 3. Локальные проверки

```bash
node scripts/validate.mjs
node --check app/app.js
node --check app/db.js
node --check app/csv.js
node --check app/backup.js
make serve
```

Перед PR все проверки должны проходить. CI повторит их на Node.js 18, 20 и 22.

## 4. Правила для данных

- `data/` и `references/` — исходные материалы, не редактируйте их в PR;
- не придумывайте людей, компании, статусы, билеты и даты;
- `checkedIn: true` допустим только для статуса `confirmed`;
- email уникален без учёта регистра;
- архивные записи не входят в показатели и обычную выдачу;
- ошибки CSV должны объяснять строку и причину, а не молча пропускаться;
- `docs/examples/backup-sample.json` — синтетический пример формата, а не
  реальные персональные данные.

Если меняется модель данных, обновите `docs/DATA-MODEL.md`, `README.md` и
`scripts/validate.mjs`.

## 5. Правила для приложения

- только HTML, CSS и современный JavaScript без фреймворков;
- без сборщиков и runtime-зависимостей;
- все пользовательские записи — в IndexedDB `eventflow-db`;
- массив в памяти и `localStorage` не заменяют базу;
- без сетевых запросов, внешних шрифтов, CDN и аналитики;
- интерфейс на русском языке;
- сохраняйте доступность: семантическая разметка, подписи, `aria-live`,
  видимый фокус, поддержку клавиатуры;
- проверяйте ширину 1440, 768 и 390 px;
- опасные действия требуют подтверждения или возможности отмены;
- не добавляйте секреты, локальные артефакты и реальные персональные данные.

## 6. Процесс OpenCode

Проект собран по воспроизводимой методике:

1. `/data-plan` — план данных и сценариев без изменения файлов;
2. человек подтверждает спорные правила и объём этапа;
3. `/data-build` — Build меняет только `app/`;
4. `/data-qa` — независимый аудит без автоматических исправлений;
5. исправления — только после согласования.

Методика описана в
[`.opencode/skills/eventflow-participant-manager/SKILL.md`](.opencode/skills/eventflow-participant-manager/SKILL.md),
правила проекта — в [`AGENTS.md`](AGENTS.md).

## 7. PR-чек-лист

- [ ] изменение соответствует задаче;
- [ ] `node scripts/validate.mjs` проходит;
- [ ] `node --check` проходит для всех модулей приложения;
- [ ] `data/` и `references/` не изменены;
- [ ] данные не выдуманы, ошибки CSV объяснены;
- [ ] проверены desktop, 768 px и 390 px;
- [ ] проверены клавиатура и видимый фокус;
- [ ] обновлены README или docs, если изменилось поведение;
- [ ] в PR нет секретов, архивов, PDF и `.DS_Store`.

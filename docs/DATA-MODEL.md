# Модель данных

## 1. Источники истины

| Что | Где | Изменяемость |
|---|---|---|
| Настройки события, статусы и билеты | `data/event-settings.json` | Только чтение |
| Демонстрационные регистрации | `data/participants.csv` | Только чтение |
| Демонстрационные ошибки CSV | `data/participants-with-errors.csv` | Только чтение |
| Данные во время работы | IndexedDB `eventflow-db` | Через интерфейс |
| Перенос между браузерами | JSON `schemaVersion: 1` | Экспорт/восстановление |
| Пример копии | `docs/examples/backup-sample.json` | Только чтение |

После первого запуска источником истины становится IndexedDB. Приложение не
читает `data/` во время работы: CSV и JSON из `data/` нужны для демонстрации и
автоматической проверки.

## 2. Модель участника

```js
{
  id: "6f0c…",                 // UUID, создаётся приложением
  name: "Анна Волкова",        // обязательное, до 120 символов
  email: "anna@example.ru",    // обязательный, уникальный без учёта регистра
  company: "ZeroCoder",        // необязательное, до 160 символов
  ticket: "vip",               // standard | business | vip
  status: "confirmed",         // new | confirmed | waitlist | cancelled
  checkedIn: true,             // только для confirmed
  registeredAt: "2026-08-18T09:20:00.000Z",
  archivedAt: null,            // null или ISO-дата
  updatedAt: "2026-08-18T09:20:00.000Z"
}
```

| Поле | Тип | Обязательное | Правило |
|---|---|---|---|
| `id` | `string` | да | UUID; уникален; генерируется приложением |
| `name` | `string` | да | Непустое, пробелы схлопываются, максимум 120 |
| `email` | `string` | да | Формат `name@example.com`, trim + lower case, уникален |
| `company` | `string` | нет | Максимум 160 символов, может быть пустым |
| `ticket` | `string` | да | Одно из значений `event-settings.json` |
| `status` | `string` | да | Одно из значений `event-settings.json` |
| `checkedIn` | `boolean` | да | `true` только при `status === "confirmed"` |
| `registeredAt` | ISO `string` | да | Разбираемая дата; в форме — текущий момент |
| `archivedAt` | ISO `string \| null` | да | `null` для активной записи |
| `updatedAt` | ISO `string \| null` | нет | Время последнего изменения |

### Статусы

| Значение | Подпись | Смысл |
|---|---|---|
| `new` | Новый | Заявка получена, участие не подтверждено |
| `confirmed` | Подтверждён | Участие подтверждено |
| `waitlist` | Лист ожидания | Мест нет, участник ждёт |
| `cancelled` | Отменён | Участие отменено |

### Типы билетов

| Значение | Подпись |
|---|---|
| `standard` | Стандартный |
| `business` | Бизнес |
| `vip` | VIP |

## 3. Бизнес-правила

- Email сравнивается без учёта регистра и пробелов по краям.
- `checkedIn: true` допустим только для `confirmed`; при смене статуса отметка
  снимается.
- Архивирование не удаляет запись: выставляется `archivedAt`, запись исчезает
  из показателей и обычной выдачи.
- Восстановление из архива возвращает `archivedAt = null`.
- Новая запись получает `registeredAt = now`; импорт сохраняет дату из CSV.
- Все изменения и импорты попадают в журнал действий.
- Архивацию можно отменить из уведомления в течение 10 секунд.

## 4. Схема IndexedDB

База: `eventflow-db`, версия `1`.

| Хранилище | Ключ | Индексы |
|---|---|---|
| `participants` | `id` | `email` (unique), `status`, `registeredAt`, `archivedAt` |
| `settings` | `key` | — |
| `activity` | `id` | — |

Запись настроек:

```js
{
  key: "event",
  name: "Практикум «Продукты с ИИ»",
  venue: "Учебный центр",
  capacity: 120,
  updatedAt: "2026-…"
}
```

Запись журнала:

```js
{
  id: "0b7d…",
  type: "imported",
  message: "Импорт CSV: добавлено 12 из 12 строк.",
  participantId: null,
  createdAt: "2026-…",
  meta: { total: 12, imported: 12, skipped: 0 }
}
```

## 5. Формат CSV

Обязательные заголовки:

```text
name,email,ticket,status,checked_in,registered_at
```

Полный набор:

```text
name,email,company,ticket,status,checked_in,registered_at
```

| Колонка | Правило |
|---|---|
| `name` | Непустое имя, до 120 символов |
| `email` | Корректный и уникальный email |
| `company` | Необязательная строка до 160 символов |
| `ticket` | `standard`, `business` или `vip` |
| `status` | `new`, `confirmed`, `waitlist` или `cancelled` |
| `checked_in` | `true/false`, `1/0`, `yes/no`, `да/нет` |
| `registered_at` | Разбираемая дата; сохраняется как ISO |

Поддерживаются UTF-8 BOM, CRLF, запятая и точка с запятой, кавычки и переводы
строк внутри кавычек. Пустые строки пропускаются.

## 7. Резервная копия JSON

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-10-31T11:24:15.819Z",
  "event": {
    "name": "Практикум «Продукты с ИИ»",
    "venue": "Учебный центр",
    "capacity": 120
  },
  "participants": [],
  "activity": []
}
```

`docs/examples/backup-sample.json` содержит 15 участников (14 активных и 1 в
архиве), 4 действия, 7 подтверждённых и 3 отмеченных прихода. Это синтетический
пример, а не реальные данные.

При восстановлении проверяются:

- наличие и поддерживаемость `schemaVersion`;
- корректность `exportedAt` и `event`;
- массивы `participants` и `activity`;
- уникальность `id` и email;
- допустимые статусы, билеты и даты;
- правило `checkedIn → confirmed`;
- структура записей журнала.

## 8. Инварианты

- 12 уникальных участников в основном CSV;
- 8 строк, 2 корректные, 6 ошибочных и 2 дубликата в демонстрационном CSV;
- 15 уникальных участников и 4 действия в примере копии;
- email всех демонстрационных записей оканчиваются на `@example.ru`;
- `checkedIn: true` встречается только у `confirmed`;
- архивные записи не входят в показатели;
- статусы и билеты совпадают с `data/event-settings.json`;
- приложение не делает сетевых запросов.

Все инварианты проверяет `node scripts/validate.mjs`.

## 9. Как обновлять данные

1. Не менять `data/` и `references/` в рамках портфолио-версии.
2. Для нового демонстрационного набора создать отдельную ветку `feature/*`.
3. Сохранить синтетический характер данных: никаких реальных людей и email.
4. Обновить `docs/DATA-MODEL.md`, README и проверки.
5. Запустить `node scripts/validate.mjs`.
6. Проверить импорт, показатели и ошибки вручную по `docs/QA-CHECKLIST.md`.

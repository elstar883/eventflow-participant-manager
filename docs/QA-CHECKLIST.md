# QA-чек-лист

## 1. Автоматические проверки

```bash
node scripts/validate.mjs
node --check app/app.js
node --check app/db.js
node --check app/csv.js
node --check app/backup.js
```

`validate.mjs` проверяет:

- наличие обязательных файлов и метаданных репозитория;
- совпадение `data/event-settings.json` со схемой `app/db.js`;
- 12 корректных строк в `data/participants.csv`;
- 8 строк, 2 корректные, 6 ошибочных и 2 дубликата в демонстрационном CSV;
- 15 участников и 4 действия в `docs/examples/backup-sample.json`;
- обязательные элементы интерфейса;
- отсутствие внешних ресурсов, `fetch`, `XMLHttpRequest`, Storage API и
  динамических импортов;
- локальные ссылки на скриншоты в README;
- синтаксис всех модулей приложения.

CI прогоняет те же проверки на Node.js 18, 20 и 22.

## 2. Запуск

```bash
make serve
# http://127.0.0.1:8080
```

Приложение должно открываться именно через локальный HTTP-сервер: ES-модули и
IndexedDB не рассчитаны на `file://`.

## 3. Первый запуск

- [ ] Заголовок события: «Практикум «Продукты с ИИ»»;
- [ ] подпись: «Учебный центр · 120 мест»;
- [ ] все показатели равны 0;
- [ ] видно пустое состояние с кнопкой «Добавить участника»;
- [ ] журнал пуст и объясняет, что действий пока нет;
- [ ] кнопки экспорта и восстановления доступны после загрузки: пустая копия
      тоже допустима;
- [ ] в консоли нет ошибок.

## 4. Импорт основного CSV

1. Нажать «Импорт CSV».
2. Выбрать `data/participants.csv`.

До подтверждения:

- [ ] в предпросмотре 12 всего, 12 корректных, 0 ошибочных, 0 дубликатов;
- [ ] кнопка предлагает «Импортировать 12 строк»;
- [ ] IndexedDB ещё не изменилась.

После подтверждения:

- [ ] таблица содержит 12 строк;
- [ ] показатели: 12 всего, 6 подтверждены, 3 пришли, 2 в листе ожидания;
- [ ] в журнале появилась запись об импорте 12 из 12 строк;
- [ ] уведомление сообщает об успешном импорте;
- [ ] повторный импорт того же файла не создаёт дубликаты.

## 5. Поиск, фильтры и сортировка

- [ ] Поиск `Анна` оставляет 1 строку;
- [ ] поиск по email и компании тоже работает;
- [ ] фильтр «Подтверждён» оставляет 6 строк;
- [ ] фильтр по типу билета сочетается со статусом;
- [ ] сортировка по имени начинается с «Алексей Попов»;
- [ ] переключение направления меняет порядок;
- [ ] счётчик показывает «Показано N из 12»;
- [ ] «Сбросить» возвращает 12 строк и очищает поля;
- [ ] при пустом результате есть объяснение и кнопка сброса.

## 6. CRUD, check-in и архив

- [ ] «Добавить участника» открывает диалог с пустыми полями;
- [ ] без имени и email показываются ошибки рядом с полями;
- [ ] email `anna.volkova@example.ru` отклоняется как занятый;
- [ ] корректный участник сохраняется, таблица и показатели обновляются;
- [ ] новая запись появляется в журнале;
- [ ] «Открыть карточку» показывает данные участника;
- [ ] «Изменить» заполняет форму текущими значениями;
- [ ] отметка прихода недоступна для `new`, `waitlist` и `cancelled`;
- [ ] подтверждённого участника можно отметить и снять отметку;
- [ ] архивация убирает строку из таблицы и уменьшает показатели;
- [ ] в уведомлении есть «Отменить»;
- [ ] отмена возвращает участника и показатели;
- [ ] архивная запись не появляется в обычной таблице.

## 7. Ошибки CSV

Импортировать `data/participants-with-errors.csv` после основного набора.

- [ ] Предпросмотр: 8 всего, 2 корректных, 6 ошибочных, 2 дубликата;
- [ ] строка 3: некорректный email;
- [ ] строка 4: не указано имя;
- [ ] строка 5: email уже есть в базе;
- [ ] строка 6: недопустимый статус `approved`;
- [ ] строка 7: `checked_in = true` при статусе `waitlist`;
- [ ] строка 8: дубликат email внутри файла;
- [ ] кнопка предлагает импортировать только 2 строки;
- [ ] отмена импорта не меняет базу;
- [ ] подтверждение добавляет только корректные строки.

## 8. Резервная копия

Экспорт:

- [ ] кнопка «Экспорт JSON» скачивает файл;
- [ ] имя файла содержит дату и время;
- [ ] JSON содержит `schemaVersion: 1`, `exportedAt`, `event`, `participants`,
      `activity`;
- [ ] количество участников и действий совпадает с экраном;
- [ ] экспорт появляется в журнале.

Восстановление:

- [ ] выбор `docs/examples/backup-sample.json` показывает предпросмотр;
- [ ] предпросмотр: 15 участников, 14 активных, 1 в архиве, 4 действия;
- [ ] подтверждены 7, отмечены как пришедшие 3;
- [ ] до подтверждения база не меняется;
- [ ] второй шаг требует чекбокс согласия;
- [ ] после подтверждения данные заменяются и видны после перезагрузки;
- [ ] неверный JSON показывает ошибку и не меняет базу.

## 9. Сохранность данных

- [ ] После перезагрузки участники остаются на месте;
- [ ] фильтры сбрасываются, данные — нет;
- [ ] записи находятся в IndexedDB `eventflow-db`;
- [ ] в базе есть `participants`, `settings` и `activity`;
- [ ] в Application → Local Storage нет пользовательских записей;
- [ ] архивные записи не входят в показатели.

## 10. Адаптивность и доступность

- [ ] На ширине 1440 px нет горизонтальной прокрутки;
- [ ] на 768 px таблица остаётся читаемой;
- [ ] на 390 px таблица превращается в карточки;
- [ ] длинные имена, email и компании переносятся;
- [ ] по `Tab` доступна ссылка «Перейти к содержимому»;
- [ ] у полей есть подписи, ошибки связаны через `aria-describedby`;
- [ ] фокус видим на кнопках, ссылках и полях;
- [ ] диалоги закрываются кнопкой отмены;
- [ ] уведомления озвучиваются через `aria-live`;
- [ ] при `prefers-reduced-motion` анимации отключаются;
- [ ] без JavaScript показывается сообщение о необходимости JS.

## 11. Сеть и безопасность

- [ ] В DevTools только локальные запросы: HTML, CSS и четыре модуля;
- [ ] нет внешних шрифтов, картинок, скриптов и CDN;
- [ ] нет `fetch`, `XMLHttpRequest`, WebSocket и `sendBeacon`;
- [ ] нет аналитики и авторизации;
- [ ] в репозитории нет `.env`, токенов, архивов, PDF и `.DS_Store`;
- [ ] все демонстрационные email синтетические.
